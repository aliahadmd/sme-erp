## Why this matters

The hottest list, filter, and report paths fall back to single-column `org_id`
indexes then sort/filter in memory: invoice lists filter by party and sort by
`created_at`; the orders lists sort every module's history by `created_at`;
void operations seq-scan the append-only `stock_moves` table; the reporting
module filters and groups on unindexed columns. Fine at seed scale — linear
degradation by year two. One additive migration fixes the lot.

  autogenerated via `alembic revision --autogenerate`.

## Scope

**In scope**: `api/app/modules/*/models.py` (index declarations only),
the new autogenerated migration file, `api/tests/test_indexes.py` (new,
optional sanity test using `pg_indexes`).

**Out of scope**: changing any query, adding new endpoints, touching the
reporting module's SQL, dropping existing indexes.

## Steps

1. **Declare indexes** — add `index=True` (or composite `Index` entries in
   `__table_args__`) for:
   - `invoicing.invoices`: composite `(org_id, invoice_type, status)`,
     `(org_id, party_id)`, single `invoice_date`, `due_date`
   - `invoicing.payments`: `(org_id, direction)`, `party_id`
   - `sales.sales_orders` / `purchasing.purchase_orders`:
     `(org_id, status)`, `(org_id, customer_id)` / `(org_id, supplier_id)`,
     `created_at`
   - `inventory.stock_moves`: `(ref_type, ref_id)`, `(org_id, moved_at)`
   - `core.notifications`: `(user_id, read_at)` (bell poll), `(type)`
   - `core.audit_logs`: already indexed on org-independent columns — verify
     only
   Match the naming convention in the existing migrations (`ix_<table>_<col>`).
2. **Autogenerate + review** — run the migration commands; open the generated
   file and confirm every `create_index` targets an existing table/column and
   no unintended diffs slipped in (autogen sometimes picks up drift — revert
   anything unrelated).
   **Verify**: `alembic upgrade head` → runs clean on the dev database.
3. **Sanity check** — `pytest tests/test_invoicing.py tests/test_inventory.py
   tests/test_documents.py -q` green (no query broke), and
   `EXPLAIN` spot-check two hot queries via psql showing index usage:
   invoice list by party, stock moves by ref.
4. `make verify` → exit 0. Commit: `perf: indexes for hot list/filter/report paths (audit 005)`.
